A VIBE-CODING WALKTHROUGH

Vibe Coding 一个微信小程序

不写一行代码你也能上手——难的从来不是写代码，是搞清楚"先做什么、后做什么"。这篇把整条路走一遍。

两幕 · 上手前想清楚 + 动手做出来
SCENE 01
场景一 · 周五晚上，小 Y 打开了微信开发者工具

她卡住的地方，根本不是写代码

小 Y 是个产品经理，脑子里憋了个小程序点子很久了。她装好了微信开发者工具，让 AI 写了第一版代码，粘进去——然后就卡住了。
不是代码报错，是一连串她答不上来的问题：要不要先注册？我没有营业执照能做吗？做完怎么让别人用上？

Vibe coding 的真相是：AI 能帮你写完 90% 的代码，但那条"从想法到上线"的流程，得你自己心里有数。
否则你会在第一步就卡住，代码写得再漂亮也发不出去。

同一件事 · 想象里两步 · 实际六步
ACT I · 上手前先想清楚

动手前的三个决定

选错了要返工。花十分钟想清楚，比写三小时代码值。

SCENE 02 · 决定一
场景二 · 第一个岔路口

你是"个人"还是"企业"？——这决定了你能做什么

注册小程序要选主体，个人和企业是两条完全不同的路。小 Y 没有公司，只能走个人主体。
好消息是：个人主体注册简单、审核宽松。坏消息是——个人主体不能碰"钱"：不能开微信支付、不能做电商交易。

个人主体 = 不碰钱的一切 · 企业主体 = 想收款就得来
一句话判断 →
你的小程序要不要在里面收钱？不收 → 个人主体，今晚就能开工。
要收 → 得先注册企业主体，或者先用个人主体把体验做出来，等验证了再升级。
SCENE 03 · 决定二
场景三 · 先别急着注册

其实你不注册也能先跑起来

很多人卡在"注册"这一步就放弃了。但真相是——写代码、本地预览这个阶段，根本不需要注册。
微信开发者工具允许用一个测试号（游客 AppID）先把项目跑起来，等做得差不多了、真要发布时再去注册换成真 AppID。

测试号 = 零门槛先跑起来 · 发布时再换真 AppID

这一步能救很多半途而废的人。
先用测试号把想法做出来、玩起来、给朋友看看——验证值不值得做，再去走注册流程。
别让"注册"这道行政门槛，挡住你验证点子的第一步。

ACT II · 动手做出来

真正的 Vibe Coding 循环

从这里开始，你和 AI 一起把它写出来。

SCENE 04
场景四 · 先认识这个"房子"的骨架

小程序就是几个页面 + 一张路由表

让 AI 帮你之前，你得看懂它给你的东西。小程序的结构很简单：一个 app.json 当总目录，注册所有页面和底部 tab；每个页面是一个文件夹，里面四个文件各管一件事。

app.json 管全局 · 每个页面四件套 · 会 HTML/CSS 就能看懂七成
给 AI 下需求时的正确姿势 →
别说"帮我做个小程序"，太空。说清楚：要几个页面、底部几个 tab、每个页面干什么。
比如"两个 tab：清单页能添加待办、打卡页记录每天完成情况"——AI 就能一把搭好骨架。
SCENE 05
场景五 · 真正开始 vibe

循环起来：你说需求，AI 写，但你得喂它"说明书"

Vibe coding 不是一句话生成全部，是一个你和 AI 来回对话的循环。
这里有个关键坑：小程序的 wx. 系列接口有很多私有约定，AI 很容易"一本正经地编"一个不存在的 API。解法是——把官方文档贴给它。

对话循环 · 卡住时不是骂 AI，是给它喂对文档

防幻觉三招：
· 用到某个 wx.xxx 接口时，把微信官方文档那一页复制给 AI；
· 让它一次只改一个小功能，改完编译验证再往下；
· 报错就把控制台完整报错原样贴回去，别自己转述。

SCENE 06
场景六 · 让两个页面"记得住"东西

没有服务器，数据靠手机本地存储打通

个人主体、纯练手的小程序，最省事的做法是不搭服务器，数据直接存在用户手机本地。
微信提供了 wx.setStorageSync / getStorageSync：清单页存进去，打卡页在 onShow 时读出来——两个页面就打通了。

存→取两个 API · 纯客户端 · 零服务器零门槛
什么时候才需要服务器？→
要多人共享数据（比如你发的内容别人也能看）、要跨设备同步时才需要。
练手、自用工具、单机清单这类，本地存储完全够——别一上来就给自己加难度。
SCENE 07
场景七 · 前人踩过的三个坑

这三个坑，几乎每个新手都会踩一次

打包进项目， 要么用已备案的 HTTPS 图床。 ✗ 别用带防盗链的外链 （小红书/微博图源会挂） 线上还要在后台配 合法域名白名单 2 AI 编 API wx. 接口私有约定多， AI 会一本正经地瞎编。 ✓ 用到就贴官方文档 给它"说明书"再让它写 报错原样贴回， 别自己转述 3 模拟器正常，真机崩 模拟器和真机有差异， 尤其是存储、接口权限。 ✓ 早点用真机预览 别等全做完才在手机试 个人主体记住： 别写任何"支付/交易"
图片 · API 幻觉 · 真机差异 · 提前知道就绕过去了
SCENE 08
场景八 · 做好了，怎么让别人用上

最后一步：注册 → 换真 AppID → 上传 → 审核 → 发布

体验做得满意了，才轮到走发布流程。这时候再去注册主体、拿到真 AppID，换掉之前的测试号。

前四步在开发者工具/后台完成 · 审核多为 1-7 天

审核别踩红线：个人主体如果代码里藏了支付、诱导分享、或做了不允许的类目，会被直接驳回。
提交前对照一遍类目要求，把不合规的功能先拿掉。

SCENE 09
场景九 · 收成三句话

所以，vibe coding 一个小程序，其实就这几件事

把整条路收成三句话：

1. 上手前先做三个决定——个人还是企业主体、要不要收钱、先用测试号免注册跑起来。

2. Vibe coding 是你和 AI 的对话循环——说清需求、一次改一点、卡住就喂它官方文档，而不是指望一句话生成全部。

3. 难的不是代码，是流程和避坑。先验证点子，满意了再走注册和发布——别让行政门槛挡在第一步。
